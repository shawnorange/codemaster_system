# GESP 七级知识对照表

> 适用场景：题库标签、课后总结、错题归因、阶段测评分析。  
> 整理原则：按照 GESP 七级思维导图知识范围，结合近年 C++ 七级真题常见落地题型进行拆分。

---

## 一、知识点总表

| 一级目录 | 二级目录 | 三级训练点 / 典型考法 |
|---|---|---|
| 数学函数 | `cmath` 头文件 | `sin`、`cos`、`tan`、`log`、`log2`、`log10`、`exp`、`pow` 等函数通常需要 `#include <cmath>`；返回值多为 `double`；输出时注意近似值与强制类型转换 |
| 数学函数 | 三角函数基本用法 | `sin(x)`、`cos(x)`、`tan(x)` 的参数是弧度，不是角度；`sin(90)` 不是 `1`；`sin(π/2)` 才接近 `1` |
| 数学函数 | 角度与弧度转换 | 角度转弧度：`rad = deg * π / 180`；常用 `acos(-1)` 获取较精确的 `π`；避免把角度直接传给三角函数 |
| 数学函数 | 三角函数输出题 | 判断 `sin(3.1415926 / 2)` 近似为 `1`；`cos(0)` 为 `1`；`tan` 在特殊角附近可能出现极大值或精度误差 |
| 数学函数 | 浮点误差 | 数学函数结果是近似值；不要直接用 `==` 判断两个浮点数是否相等；可使用 `fabs(a-b) < eps` 判断近似相等 |
| 数学函数 | 对数函数概念 | `log(x)` 表示自然对数，以 `e` 为底；`log10(x)` 表示常用对数；`log2(x)` 表示以 2 为底的对数 |
| 数学函数 | 对数函数返回类型 | `log(256)` 的返回值类型是 `double`，结果不是 `8`；`log2(256)` 才接近 `8`；`(int)log(8)` 是对自然对数结果取整 |
| 数学函数 | 对数函数定义域 | 对数函数要求参数大于 `0`；`log(0)`、`log(-1)` 不符合数学定义，程序结果不可按正常数学值理解 |
| 数学函数 | 换底公式 | `log_a(b) = log(b) / log(a)`；在程序中常用 `log(x) / log(base)` 计算任意底数的对数 |
| 数学函数 | 指数函数 `exp` | `exp(x)` 表示 `e^x`；例如 `exp(2)` 约为 `7.389`，强制转换为 `int` 后得到 `7` |
| 数学函数 | 幂函数 `pow` | `pow(a,b)` 返回 `a^b` 的近似 `double` 结果；用于整数幂时要注意浮点误差和强制类型转换 |
| 数学函数 | `^` 不是乘方 | C++ 中 `^` 是按位异或，不是幂运算；`3 ^ 2` 的结果不是 `9`；求平方应写 `x * x` 或 `pow(x, 2)` |
| 数学函数 | 数学函数与类型转换 | `(int)log(8)`、`(int)exp(2)`、`(int)pow(2, 10)` 常考截断规则；强制转换不是四舍五入，而是直接舍弃小数部分 |
| 数学函数 | 数学函数与比较 | 判断结果范围时要结合函数单调性，如 `exp(x) > 0`；`log(x)` 在 `0<x<1` 时为负，不能默认所有数学函数结果都为正 |
| 数学函数 | 常见真题陷阱 | `log`、`log2` 混淆；角度、弧度混淆；`^` 和乘方混淆；`double` 输出近似值与整数强转混淆 |
| 复杂动态规划 | 动态规划基本结构 | 明确状态含义、初始化、状态转移、答案位置；七级更强调从代码反推状态转移和复杂度 |
| 复杂动态规划 | 状态设计 | `dp[i]`、`dp[i][j]`、`f[l][r]` 分别代表一维状态、二维状态、区间状态；必须先说明“这个数组格子存的是什么” |
| 复杂动态规划 | 初始化边界 | `dp[0]`、`dp[i][0]`、`dp[0][j]`、`f[i][i]` 是常见边界；初始化错误会导致整张表后续都错 |
| 复杂动态规划 | 二维动态规划 | 常见形式为双重循环填表；如路径计数、网格最值、字符串匹配、背包二维表等 |
| 复杂动态规划 | 二维 DP 遍历顺序 | 当前状态依赖上方、左方、左上方时，通常从小到大填表；遍历顺序必须保证依赖状态已经被算出 |
| 复杂动态规划 | 动态规划最值优化 | 常见表达为 `dp[i] = max/min(...)`；考查“保留历史最优”而不是只看当前一步 |
| 复杂动态规划 | 路径计数 DP | `path[i][j] = path[i-1][j] + path[i][j-1]`；注意第一行、第一列的初始化和数组下标范围 |
| 复杂动态规划 | 0/1 背包模型 | 每个物品只能选一次；二维写法 `dp[i][j]` 表示前 `i` 个物品、容量 `j` 的最优值；常见复杂度 `O(nW)` |
| 复杂动态规划 | 背包滚动数组 | 二维 `dp[i][j]` 可优化为一维 `dp[j]`；0/1 背包容量必须倒序枚举，防止同一物品被重复使用 |
| 复杂动态规划 | 区间动态规划 | 状态通常写作 `f[l][r]`，表示区间 `[l,r]` 的最优值；常见于合并石子、矩阵链、括号匹配等 |
| 复杂动态规划 | 区间 DP 枚举长度 | 通常先枚举区间长度 `len`，再枚举左端点 `l`，右端点 `r = l + len - 1`，最后枚举断点 `k` |
| 复杂动态规划 | 区间 DP 转移 | 常见转移：`f[l][r] = min(f[l][k] + f[k+1][r] + cost)`；重点是断点范围和代价计算 |
| 复杂动态规划 | 区间 DP 与前缀和 | 区间代价常用前缀和快速求 `sum(l,r)`；避免每次重新循环求区间和导致复杂度升高 |
| 复杂动态规划 | LIS 概念 | 最长上升子序列要求保持原有相对顺序，但不要求连续；严格上升常用条件 `a[j] < a[i]` |
| 复杂动态规划 | LIS 朴素 DP | `dp[i]` 表示以 `a[i]` 结尾的最长上升子序列长度；转移：若 `a[j] < a[i]`，`dp[i] = max(dp[i], dp[j] + 1)` |
| 复杂动态规划 | LIS 输出追踪 | 给定输入序列，能逐步写出每个 `dp[i]` 的值；注意重复元素在“严格上升”中不能接在一起 |
| 复杂动态规划 | LIS 二分优化 | 使用 `tail[len]` 维护长度为 `len` 的上升子序列最小结尾；复杂度可由 `O(n^2)` 优化到 `O(n log n)` |
| 复杂动态规划 | LCS 概念 | 最长公共子序列要求两个序列中都出现且相对顺序一致，不要求连续；常与最长公共子串区分 |
| 复杂动态规划 | LCS 二维 DP | `dp[i][j]` 表示第一个序列前 `i` 个、第二个序列前 `j` 个的 LCS 长度；若相等取 `dp[i-1][j-1]+1`，否则取两边最大值 |
| 复杂动态规划 | LCS 与公共字符 | LCS 长度为 5，只能说明至少存在长度为 5 的公共子序列；不能推出编辑距离、公共子串长度或两个字符串长度相等 |
| 复杂动态规划 | 最长公共子串 | 公共子串要求连续；若 `s1[i-1] == s2[j-1]`，常用 `dp[i][j] = dp[i-1][j-1] + 1`，否则归零 |
| 复杂动态规划 | 滚动数组优化 | 当当前行只依赖上一行时，可用两行或一行数组优化空间；常见于 LCS、背包、网格 DP |
| 复杂动态规划 | 滚动数组依赖方向 | 使用一维滚动时要判断状态依赖方向；正序、倒序写错会改变题意 |
| 复杂动态规划 | 递归、记忆化与递推 | 朴素递归可能指数级；加入记忆化后减少重复计算；递推实现通常更稳定，也更容易控制空间 |
| 复杂动态规划 | 递推式复杂度 | `T(n)=2T(n-1)+1` 常对应指数增长；记忆化斐波那契常为 `O(n)`；朴素斐波那契接近指数级 |
| 复杂动态规划 | DP 复杂度估算 | 时间复杂度通常与“状态数 × 每个状态转移次数”有关；空间复杂度通常与状态表大小有关 |
| 复杂动态规划 | DP 代码补全题 | 常考横线处填 `dp[i] = max(dp[i], dp[j] + 1)`、`visited[x]=true`、状态转移公式等 |
| 复杂动态规划 | 常见真题陷阱 | 子序列与子串混淆；滚动数组方向错误；区间 DP 枚举顺序错误；递归复杂度误判；把贪心误认为一定最优 |
| 图的定义及遍历 | 图的基本概念 | 图由顶点和边组成；边可以有向或无向；边可带权或不带权；二叉树、社交网络、迷宫都可以抽象成图 |
| 图的定义及遍历 | 无向图 | 边没有方向；一条边连接两个顶点；顶点的度表示与它相连的边数；所有顶点度数之和等于边数的两倍 |
| 图的定义及遍历 | 有向图 | 边有方向；顶点有入度和出度；所有顶点入度之和等于边数，出度之和也等于边数，入度加出度总和为边数两倍 |
| 图的定义及遍历 | 简单图 | 简单图通常不含自环和重边；无向完全图最多 `n(n-1)/2` 条边，有向完全图最多 `n(n-1)` 条边 |
| 图的定义及遍历 | 路径与环 | 路径是顶点和边组成的访问序列；环表示从某个顶点出发经过若干边又回到自身；有向图需要方向一致 |
| 图的定义及遍历 | 连通图 | 无向图中任意两个顶点之间都存在路径，则称为连通图；非连通图可以分成多个连通块 |
| 图的定义及遍历 | 连通分量 | 无向图中极大的连通子图称为连通分量；要让 `k` 个连通分量连成一个整体，至少需要添加 `k-1` 条边 |
| 图的定义及遍历 | 弱连通与强连通 | 有向图忽略方向后连通称为弱连通；任意两个顶点都能互相到达称为强连通；强连通要求更严格 |
| 图的定义及遍历 | 强连通分量 | 有向图中互相可达的一组极大顶点集合；常考根据图判断强连通分量个数 |
| 图的定义及遍历 | 树与图的关系 | 树是特殊图；`n` 个结点的树有 `n-1` 条边；连通无向图的生成树也有 `n-1` 条边 |
| 图的定义及遍历 | 森林与二叉树映射 | 任意森林可以用二叉树方式表达和存储；树转图时要注意边的方向和连通性变化 |
| 图的定义及遍历 | DAG 有向无环图 | 有方向且没有环；课程先修关系、技能依赖关系常可抽象为 DAG，但不一定是树 |
| 图的定义及遍历 | 图的邻接矩阵 | 用二维数组表示顶点之间是否有边或边权；空间复杂度 `O(V^2)`；判断两点是否相邻为 `O(1)` |
| 图的定义及遍历 | 邻接矩阵读图 | 无边可用 `0`、`false` 或 `inf` 表示；有向图矩阵不一定对称，无向图矩阵通常对称 |
| 图的定义及遍历 | 图的邻接表 | 每个顶点保存相邻顶点列表；空间复杂度通常为 `O(V+E)`；适合稀疏图 |
| 图的定义及遍历 | 邻接表读图 | 无向图一条边通常要存两次；有向图只按方向存一次；出边邻接表和入边邻接表含义不同 |
| 图的定义及遍历 | 图存储复杂度 | 邻接矩阵遍历一个点的所有邻居常需 `O(V)`；邻接表遍历所有边整体通常为 `O(V+E)` |
| 图的定义及遍历 | 广度优先搜索 BFS | 使用队列，从起点一层一层向外扩展；适合无权图最短路、层数、最少步数问题 |
| 图的定义及遍历 | BFS 基本结构 | 入队起点并标记访问；循环取队首；枚举邻居；未访问则标记并入队；队列先进先出 |
| 图的定义及遍历 | BFS 遍历序列 | 同一层中邻居访问顺序可能影响输出序列；BFS 序列不一定唯一，但必须满足层次顺序 |
| 图的定义及遍历 | BFS 复杂度 | 使用邻接表完整遍历复杂度为 `O(V+E)`；使用邻接矩阵时通常为 `O(V^2)` |
| 图的定义及遍历 | 深度优先搜索 DFS | 沿一条路尽量向深处走，走不通再回退；主要体现递归、栈和回溯思想 |
| 图的定义及遍历 | DFS 递归实现 | 函数进入时标记当前点；递归访问未访问邻居；天然使用函数调用栈 |
| 图的定义及遍历 | DFS 非递归实现 | 可以使用 `stack` 手动模拟；入栈顺序会影响最终访问序列 |
| 图的定义及遍历 | DFS 遍历序列 | 邻接点枚举顺序不同，DFS 结果可能不同；判断序列时要看是否符合“走到底再回退”的规则 |
| 图的定义及遍历 | DFS 与回溯 | DFS 常用于路径搜索、判环、连通块、枚举方案；“撤销选择”是回溯题的重要特征 |
| 图的定义及遍历 | 遍历非连通图 | 从一个起点只能访问其所在连通块；若要遍历全图，需要对每个未访问点重新启动 BFS 或 DFS |
| 图的定义及遍历 | 图遍历与树遍历 | 二叉树前序、中序、后序本质上属于深度优先遍历；层序遍历对应广度优先遍历 |
| 图的定义及遍历 | 遍历中的 `visited` | 标记数组防止重复访问和死循环；通常在入队或入栈时立即标记，而不是弹出时才标记 |
| 图的定义及遍历 | 常见真题陷阱 | DFS 说成必须用队列；BFS 说成必须用递归；邻接表边数统计错误；有向图入度出度公式混淆 |
| 图论算法 | 泛洪算法概念 | Flood Fill 本质是从起点出发，在满足条件的区域内进行 BFS 或 DFS 扩展；常见于染色、连通块、迷宫、地图区域 |
| 图论算法 | 二维网格建图 | 每个格子看作一个顶点，相邻格子之间看作边；常用四方向或八方向移动 |
| 图论算法 | 四连通 | 只允许上、下、左、右四个方向；常用 `dx[4] = {-1,1,0,0}`，`dy[4] = {0,0,-1,1}` |
| 图论算法 | 八连通 | 在四方向基础上加入四个对角方向；适合需要对角相邻也算连通的图像问题 |
| 图论算法 | 边界判断 | 每次扩展前判断 `nx`、`ny` 是否越界；常见条件为 `0 <= nx < n` 且 `0 <= ny < m` |
| 图论算法 | 障碍与可走条件 | 只有满足同色、非墙、未访问、值相同等条件的格子才能继续扩展 |
| 图论算法 | 染色问题 | 从起点开始把同一区域改成新颜色；若新颜色与原颜色相同，应避免重复搜索 |
| 图论算法 | 连通块计数 | 枚举每个格子；若未访问且符合条件，则启动一次 BFS/DFS，连通块数量加一 |
| 图论算法 | 面积统计 | 在 flood fill 搜索过程中统计访问格子数量；常用于求岛屿面积、区域大小 |
| 图论算法 | 周长统计 | 搜索每个区域格子时，若相邻方向越界或是非区域格子，则周长加一 |
| 图论算法 | 迷宫可达性 | 判断起点是否能到终点；BFS 和 DFS 都能判断可达，BFS 更适合求最短步数 |
| 图论算法 | 最短路与 BFS | 在无权图或每步代价相同的网格中，BFS 第一次到达终点通常就是最短距离 |
| 图论算法 | DFS 栈溢出风险 | 大地图递归 DFS 可能导致栈溢出；工程上常用 BFS 队列或手写栈避免递归过深 |
| 图论算法 | Flood Fill 与图搜索 | 泛洪算法不只适用于图像，也可以看作一般图上的搜索；二维网格只是最常见模型 |
| 图论算法 | 多源扩展 | 多个起点同时入队，可用于同时向外扩散的问题；注意初始点都要先标记 |
| 图论算法 | 常见真题陷阱 | 忘记 `visited`；递归爆栈；四连通和八连通混淆；把 flood fill 误认为只能递归或只能二维 |
| 哈希表 | 哈希表基本概念 | 用哈希函数把关键字映射到数组下标；目标是快速插入、查找和统计 |
| 哈希表 | 哈希函数 | 常见形式 `h(x) = x % p`；字符串也可以通过多项式哈希等方式映射为整数 |
| 哈希表 | 表长与取模 | 取模结果必须落在合法下标范围内；表长、模数、地址范围要区分清楚 |
| 哈希表 | 选择素数取模 | 模数常选素数是为了让分布更均匀、减少规律性冲突，但不能保证完全没有冲突 |
| 哈希表 | 哈希冲突 | 不同关键字可能映射到同一地址；冲突是哈希表必须处理的问题，不是程序异常 |
| 哈希表 | 装载因子 | 装载因子越大，冲突概率通常越高；不考虑扩容时，查找和插入性能会逐渐下降 |
| 哈希表 | 开放定址法 | 发生冲突后继续在表内寻找其他空位；包括线性探测、二次探测、双重哈希等 |
| 哈希表 | 线性探测 | 冲突后依次向后找空位，到末尾后回到开头；常考模拟某个数最终存入哪个地址 |
| 哈希表 | 循环查找 | 线性探测要注意下标循环：`k = (k + 1) % table_size`；不能越界访问 |
| 哈希表 | 开放定址查找 | 查询时从哈希位置开始按相同探测规则查找；遇到空位通常可判定不存在，但删除会让问题变复杂 |
| 哈希表 | 开放定址删除 | 删除不能简单清空，否则可能截断后续探测链；通常需要懒删除标记 |
| 哈希表 | 链地址法 | 每个哈希槽挂一个链表、vector 或其他结构；所有映射到该槽的元素都放在这个桶中 |
| 哈希表 | 冲突桶结构 | 冲突元素可用单链表、平衡树、二级哈希表等管理；不能直接覆盖旧元素或随意丢弃新元素 |
| 哈希表 | 平均与最坏复杂度 | 哈希表平均查找可接近 `O(1)`；最坏情况下所有元素落入同一槽，查找可能退化到 `O(n)` |
| 哈希表 | 平均成功查找长度 | 计算成功查找时的比较次数平均值；常与线性探测、链地址法模拟结合 |
| 哈希表 | 哈希表应用 | 去重、计数、快速判断是否出现、映射关系、字符串匹配、图节点编号压缩等 |
| 哈希表 | C++ 容器应用 | `unordered_map`、`unordered_set` 底层思想与哈希表相关；平均复杂度接近 `O(1)`，但仍可能退化 |
| 哈希表 | 常见真题陷阱 | 覆盖冲突元素、丢弃冲突元素、认为素数取模无冲突、认为哈希查找永远 `O(1)`、线性探测模拟下标错误 |
