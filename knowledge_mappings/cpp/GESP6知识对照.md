## 一、知识点总表

| 一级目录 | 二级目录 | 三级训练点 / 典型考法 |
|---|---|---|
| 树 | 树的基本概念 | 根结点、父结点、子结点、兄弟结点、叶子结点；结点的度、树的度、层数、深度、高度；树有 `n` 个结点时边数为 `n-1` |
| 树 | 二叉树基本概念 | 每个结点最多有两个孩子；左孩子、右孩子；空树、单结点树；二叉树不等于每个结点都有两个孩子 |
| 树 | 二叉树结点结构 | `struct TreeNode { int val; TreeNode* left; TreeNode* right; };`；用指针连接左右子树；空孩子用 `nullptr` 表示 |
| 树 | 树的遍历概念 | 深度优先遍历与广度优先遍历；访问顺序决定输出结果；遍历前先判断空结点 |
| 树 | 前序遍历 | 根、左、右；常见代码顺序为 `cout`、递归左子树、递归右子树；可用栈模拟 |
| 树 | 中序遍历 | 左、根、右；二叉排序树的中序遍历结果为有序序列；输出顺序判断题高频 |
| 树 | 后序遍历 | 左、右、根；常用于释放树结点、求子树信息后再处理根结点 |
| 树 | 层序遍历 | 使用队列从上到下、从左到右访问；常用于 BFS、完全二叉树判断、每层最大值 |
| 树 | 根据遍历序列还原二叉树 | 前序 + 中序可以唯一确定二叉树；后序 + 中序可以唯一确定二叉树；前序 + 后序通常不能唯一确定 |
| 树 | 后序遍历推导 | 已知前序、中序时，先找根，再分左右子树，最后按左、右、根输出；注意字符区间不要切错 |
| 树 | 树的深度 / 高度 | 空树深度常记为 0；非空树深度为左右子树深度最大值加 1；题目可能按“结点数”或“边数”定义深度 |
| 树 | 叶子结点统计 | 没有左孩子也没有右孩子的结点是叶子；DFS 或 BFS 遍历时统计 |
| 树 | 完全二叉树 | 除最后一层外均填满，最后一层从左到右连续填充；不是所有结点都有两个孩子 |
| 树 | 完全二叉树判断 | 层序遍历时，一旦遇到空结点，后面不能再出现非空结点；常用 `hasNull` 标记 |
| 树 | 完全二叉树数组存储 | 若下标从 1 开始，左孩子为 `2*i`，右孩子为 `2*i+1`，父结点为 `i/2` |
| 树 | 0 下标数组存储二叉树 | 若下标从 0 开始，左孩子为 `2*i+1`，右孩子为 `2*i+2`，父结点为 `(i-1)/2` |
| 树 | 满二叉树与完全二叉树区分 | 满二叉树每层都满；完全二叉树最后一层可以不满但必须靠左；不要把“完全”理解成“每个结点都有两个孩子” |
| 树 | 二叉排序树基本性质 | 左子树所有结点值小于根，右子树所有结点值大于根；每棵子树也满足该性质 |
| 树 | 二叉排序树查找 | `target < root->val` 搜左子树，`target > root->val` 搜右子树；平均复杂度常为 `O(log n)`，最坏退化为 `O(n)` |
| 树 | 二叉排序树插入 | 找到空位置后创建新结点；小于当前结点往左，大于当前结点往右；递归返回当前根结点 |
| 树 | 二叉排序树删除 | 删除叶子结点、只有一个孩子的结点、有两个孩子的结点；两个孩子时常用前驱或后继替换 |
| 树 | 二叉排序树中序性质 | 中序遍历结果递增；判断一棵树是否是 BST 时可以利用上下界或中序序列 |
| 树 | 哈夫曼树 | 又称最优二叉树；带权路径长度 WPL 最小；权值越大的叶子通常越靠近根 |
| 树 | 哈夫曼树构造 | 每次选出权值最小的两个结点合并成新结点；新结点权值为两者之和；重复直到只剩一棵树 |
| 树 | WPL 计算 | `WPL = Σ(权值 × 编码长度)`；也可以把每次合并产生的新权值累加得到 WPL |
| 基于树的编码 | 哈夫曼编码基本思想 | 变长编码；频率高的字符使用较短编码，频率低的字符使用较长编码；适合数据压缩 |
| 基于树的编码 | 前缀编码 | 任意一个字符的编码都不是另一个字符编码的前缀；因此可以不加分隔符进行唯一解码 |
| 基于树的编码 | 哈夫曼编码生成 | 从根到叶子走路径，左边记 0、右边记 1；叶子对应字符，路径对应编码 |
| 基于树的编码 | 哈夫曼编码长度 | 字符所在叶子越深，编码越长；判断题常考“频率越高是否离根越近” |
| 基于树的编码 | 哈夫曼编码不唯一 | 左右孩子交换会得到不同编码，但编码长度和 WPL 不变；不要把“可唯一解码”理解成“编码方案唯一” |
| 基于树的编码 | 哈夫曼编码解码 | 从根开始按 0/1 走到叶子，输出字符后回到根；前缀编码保证不会歧义 |
| 基于树的编码 | 哈夫曼编码实现 | 可用优先队列、排序数组或双队列选最小；结构体中保存权值、左右孩子、字符下标 |
| 基于树的编码 | 格雷编码基本概念 | 相邻两个编码只有一位二进制位不同；常用于减少状态切换错误 |
| 基于树的编码 | 反射法生成格雷编码 | `n` 位格雷码由 `n-1` 位格雷码生成：前半部分加 `0`，后半部分逆序加 `1` |
| 基于树的编码 | 格雷编码递归实现 | `grayCode(n)` 可先生成 `grayCode(n-1)`，再构造新数组；注意第二轮必须逆序遍历 |
| 基于树的编码 | 格雷编码迭代实现 | 从 `0, 1` 开始，每次保存当前长度 `current_size`，逆序追加 `1 + 原编码`，再给原编码前加 `0` |
| 基于树的编码 | 格雷编码数量 | `n` 位格雷编码共有 `2^n` 个；生成全部编码的时间和空间都与 `2^n` 相关 |
| 基于树的编码 | 格雷编码相邻判断 | 判断两个二进制串是否只相差一位；“某编码之后可能是什么”本质是判断汉明距离是否为 1 |
| 搜索算法 | DFS 基本思想 | 深度优先搜索：沿一条路径深入到不能再深入，再回退尝试其他分支；常用递归或栈实现 |
| 搜索算法 | DFS 递归模板 | 先判断边界和访问状态，再处理当前结点，最后递归访问相邻结点；二叉树中常见为访问左右子树 |
| 搜索算法 | DFS 非递归模板 | 使用 `stack` 保存待访问结点；要得到前序“根左右”，通常先压右孩子，再压左孩子 |
| 搜索算法 | DFS 访问标记 | 图或网格搜索需要 `visited`，避免重复访问或死循环；二叉树通常不需要 visited |
| 搜索算法 | BFS 基本思想 | 广度优先搜索：按层扩展，先访问距离近的状态；常用队列实现 |
| 搜索算法 | BFS 队列模板 | `queue` 入队起点；循环中取 `front`、`pop`，再把合法相邻状态入队；先判空再取队首 |
| 搜索算法 | 二叉树 BFS | 层序遍历输出、计算每层最大值、计算最短层数、判断完全二叉树；队列中保存 `TreeNode*` |
| 搜索算法 | 二叉树 DFS | 前序、中序、后序都属于 DFS；代码顺序直接决定遍历类型 |
| 搜索算法 | 二叉排序树搜索 | 利用 BST 性质剪枝，不必遍历整棵树；查找方向由目标值和当前结点值决定 |
| 搜索算法 | 搜索复杂度 | 二叉树 DFS/BFS 通常访问每个结点一次，为 `O(n)`；图搜索通常为 `O(V+E)` |
| 搜索算法 | DFS 与 BFS 区分 | DFS 用栈或递归，适合路径枚举；BFS 用队列，适合层序和最短步数 |
| 搜索算法 | 搜索边界 | 空树、空队列、空栈、越界、重复访问；访问 `top/front` 前必须保证容器非空 |
| 简单动态规划 | 动态规划基本思想 | 把问题拆成有重叠的子问题；保存中间结果，避免重复计算；核心是状态定义和状态转移 |
| 简单动态规划 | 最优子结构 | 大问题的最优解可以由小问题的最优解推出；选择题常与贪心、分治进行区分 |
| 简单动态规划 | 重叠子问题 | 多次计算同一个子问题时适合使用 DP；朴素递归斐波那契会产生大量重复计算 |
| 简单动态规划 | 一维动态规划状态定义 | `dp[i]` 表示前 `i` 个元素、到第 `i` 级台阶、以第 `i` 个位置结尾等；必须先说清楚含义 |
| 简单动态规划 | 一维 DP 初始值 | 明确 `dp[0]`、`dp[1]`、`dp[2]`；注意 `n=0`、`n=1`、`n=2` 的边界 |
| 简单动态规划 | 爬楼梯 / 斐波那契 | `dp[i] = dp[i-1] + dp[i-2]`；青蛙跳台阶、兔子繁殖、路径计数等常见模型 |
| 简单动态规划 | 不相邻元素最大和 | `dp[i] = max(dp[i-1], nums[i] + dp[i-2])`；表示选或不选第 `i` 个元素 |
| 简单动态规划 | 最大值 / 最小值转移 | 常见写法为 `dp[i] = max(...)` 或 `dp[i] = min(...)`；不要只做简单累加 |
| 简单动态规划 | 滚动变量优化 | 只依赖前一项或前两项时，可用变量代替数组；更新顺序不能写反 |
| 简单动态规划 | 简单背包问题 | 有容量、有物品、有价值；核心问题是“选不选某个物品”或“能否凑出某个容量” |
| 简单动态规划 | 01 背包 | 每个物品最多选一次；一维优化时容量循环通常从大到小，避免同一物品被重复使用 |
| 简单动态规划 | 完全背包入门 | 每个物品可以重复选；一维优化时容量循环通常从小到大；注意与 01 背包区分 |
| 简单动态规划 | 背包初始化 | `dp[0]` 通常表示容量为 0 的状态；求最大价值、可行性、方案数时初始化方式不同 |
| 简单动态规划 | 背包复杂度 | 常见复杂度为 `O(n * V)`；`n` 是物品数，`V` 是容量；不能误判为线性复杂度 |
| 面向对象 | 面向对象思想 | 用类描述一类对象的属性和行为；对象是类的实例；核心特性包括封装、继承、多态 |
| 面向对象 | 类与对象 | 类是模板，对象是具体实例；`Circle c(5.0); c.getArea();` 是创建对象并调用成员函数 |
| 面向对象 | `class` 与 `struct` | `class` 默认访问权限为 `private`，`struct` 默认访问权限为 `public`；二者都可以有成员函数 |
| 面向对象 | 成员变量与成员函数 | 成员变量描述状态，成员函数描述行为；对象用 `.` 访问，指针用 `->` 访问 |
| 面向对象 | 访问控制 | `private` 类外不能直接访问；`protected` 可被派生类访问；`public` 提供外部接口 |
| 面向对象 | 封装 | 数据通常设为私有，通过公有成员函数读取或修改；避免在类外直接改私有成员 |
| 面向对象 | 构造函数 | 名字与类名相同，无返回类型；对象创建时自动调用；可用初始化列表初始化成员和父类 |
| 面向对象 | 默认构造函数 | 如果没有用户声明的构造函数，编译器可能隐式生成默认构造函数；一旦自定义带参构造，默认构造可能不再自动可用 |
| 面向对象 | 复制构造函数 | `MyClass obj2 = obj1;` 会调用复制构造函数；若没有自定义，编译器会生成默认复制构造 |
| 面向对象 | 析构函数 | 形式为 `~ClassName()`；无返回类型、无参数，不能重载；对象销毁或 `delete` 时调用 |
| 面向对象 | 虚析构函数 | 通过基类指针删除派生类对象时，基类析构函数通常应声明为 `virtual`，避免资源释放不完整 |
| 面向对象 | 静态成员变量 | 属于类而不是某个对象；常用 `类名::变量` 访问；通常需要在类外定义一次 |
| 面向对象 | 静态成员函数 | 不依赖具体对象，可用 `类名::函数()` 调用；不能直接访问非静态成员 |
| 面向对象 | 继承 | 派生类获得基类的属性和行为；常见写法 `class Dog : public Animal`；构造派生类时要先构造基类 |
| 面向对象 | 基类构造函数调用 | 派生类构造函数初始化列表中使用 `Animal(name)` 调用父类构造；C++ 中没有 `super(name)` 这种写法 |
| 面向对象 | 多态 | 基类指针或引用调用虚函数时，根据对象真实类型决定执行哪个版本；体现“同一接口，不同表现” |
| 面向对象 | 虚函数 | 使用 `virtual` 支持运行时多态；构造函数不能是虚函数；普通函数没有虚函数机制时可能调用基类版本 |
| 面向对象 | `override` | 表示派生类函数重写基类虚函数；函数名、参数列表、`const` 等必须匹配，否则编译错误 |
| 面向对象 | 对象指针与动态创建 | `Animal* p = new Dog(...); p->speak(); delete p;`；注意配套 `new/delete` 和虚析构函数 |
| 面向对象 | 空指针访问 | `MyClass* obj = NULL; obj->display();` 属于空指针访问风险；应先创建有效对象 |
| 面向对象 | 内部类 | 类中可以嵌套定义类；类外访问内部类常用 `Outer::Inner`；还要受访问权限限制 |
| 面向对象 | 运算符重载 | 自定义类若要直接 `cout << obj` 或使用 `obj[i]`，需要重载相应运算符；否则可能编译错误 |
| 栈和队列 | 栈的基本概念 | 后进先出 LIFO；最后压入的元素最先弹出；常见操作有 `push`、`top`、`pop`、`empty` |
| 栈和队列 | STL 栈操作 | `top()` 只查看栈顶，`pop()` 删除栈顶且不返回值；必须先 `top()` 再 `pop()` |
| 栈和队列 | 栈的输出顺序 | 依次压入 `1,2,3,4,5`，弹出顺序为 `5,4,3,2,1`；常和队列对比考查 |
| 栈和队列 | 栈的应用 | 括号匹配、十进制转二进制、撤销操作、函数调用、DFS 非递归实现 |
| 栈和队列 | 括号匹配 | 左括号入栈；遇到右括号先判断栈空，再取栈顶比较，最后弹出 |
| 栈和队列 | 进制转换 | 不断取余入栈，再从栈顶弹出得到高位到低位的结果；注意 `n=1`、`n=0` 边界 |
| 栈和队列 | 链式栈 | 新结点入栈常写 `s->next = top; top = s;`；指针更新顺序不能反 |
| 栈和队列 | 队列的基本概念 | 先进先出 FIFO；先进入的元素先离开；常见操作有 `push`、`front`、`pop`、`empty` |
| 栈和队列 | STL 队列操作 | `front()` 查看队首，`back()` 查看队尾，`pop()` 删除队首；队列没有 `top()` |
| 栈和队列 | 队列的输出顺序 | 依次入队 `1,2,3,4,5`，出队顺序为 `1,2,3,4,5`；常与栈混合阅读代码 |
| 栈和队列 | 队列的应用 | 排队模拟、BFS、层序遍历、生产者消费者缓冲区、任务调度的基础模型 |
| 栈和队列 | 循环队列基本思想 | 用数组加 `front`、`rear` 和取模运算复用空间；避免普通队列假溢出 |
| 栈和队列 | 循环队列队空 | 常见约定为 `front == rear`；表示队列中没有元素 |
| 栈和队列 | 循环队列队满 | 牺牲一个位置区分空和满时，队满条件为 `(rear + 1) % N == front`；数组长度 `N` 最多存 `N-1` 个元素 |
| 栈和队列 | 循环队列入队 | 先判断是否满，再写入 `arr[rear] = x`，最后 `rear = (rear + 1) % N`；有些题目定义顺序可能不同，要看题干 |
| 栈和队列 | 循环队列出队 | 先判断是否空，再取 `arr[front]`，最后 `front = (front + 1) % N`；删除的是队首元素 |
| 栈和队列 | 循环队列元素个数 | 在牺牲一个空位的模型中，元素个数常为 `(rear - front + N) % N` |
| 栈和队列 | 循环队列模拟 | 按操作序列逐步更新 `front` 和 `rear`；注意取模后可能回到 0 |
| 栈和队列 | 栈队列安全操作 | 访问 `top/front` 前先判断非空；入循环队列前先判断非满；避免越界和未定义行为 |

## 五、错题归因建议

学生错题可以优先按以下方式归类：

1. **面向对象机制错误**
   - 类和对象概念混淆
   - `class` 默认私有、`struct` 默认公有记错
   - 构造函数、复制构造函数、析构函数调用时机不清楚
   - `private`、`protected`、`public` 访问权限判断错误
   - 封装、继承、多态三个概念对应代码场景不清楚
   - 虚函数、`override`、虚析构函数相关判断错误

2. **栈和队列操作错误**
   - 栈后进先出、队列先进先出混淆
   - `top()`、`front()`、`back()` 用法混淆
   - `pop()` 没有返回值这一点不熟
   - 栈和队列混合代码输出顺序判断错误
   - 括号匹配、进制转换、撤销操作模型不熟

3. **循环队列模拟错误**
   - 队空、队满条件记反
   - 忘记循环取模
   - 不知道牺牲一个空位时容量为 `N` 只能存 `N-1` 个元素
   - `front`、`rear` 的含义没有按题目定义分析
   - 入队和出队后指针位置更新错误

4. **树结构与遍历错误**
   - 树的度、深度、高度、叶子结点概念混乱
   - 前序、中序、后序、层序遍历顺序混乱
   - 根据遍历序列还原二叉树时左右子树范围切错
   - 完全二叉树、满二叉树、平衡二叉树、二叉排序树混淆
   - 完全二叉树数组下标公式混用 0 起点和 1 起点
   - BST 查找、插入、删除方向和边界错误

5. **哈夫曼编码与格雷编码错误**
   - 哈夫曼树构造时没有每次选最小两个权值
   - WPL 计算忘记乘路径长度
   - 频率高低和编码长度关系判断反了
   - 认为哈夫曼编码唯一
   - 格雷编码生成时忘记“镜像反射”
   - 判断相邻格雷码时没有检查是否只差一位

6. **搜索算法错误**
   - DFS 和 BFS 的基本思想不清楚
   - DFS 用递归或栈，BFS 用队列的对应关系混乱
   - 搜索前没有处理空结点、越界、已访问等边界
   - 二叉树遍历代码顺序和输出顺序对应不上
   - 层序遍历和完全二叉树判断不会用队列模拟

7. **简单动态规划与背包错误**
   - 没有先定义 `dp[i]` 的含义就写公式
   - 初始值和边界条件漏写
   - 把递归、递推、动态规划混为一谈
   - 不相邻最大和、爬楼梯等典型模型识别不出来
   - 01 背包和完全背包的容量循环方向混淆
   - 背包容量、物品数量、价值数组下标对应错误
