| 二分算法 | 第一个大于 | upper_bound：若 `a[mid] > x`，收缩右边界；否则左边界右移 |
| 二分算法 | 最后一个小于等于 | 注意使用上取中位数，避免 `left = mid` 死循环 |
| 二分算法 | 重复元素位置 | 查找第一个 target、最后一个 target；不能找到一个就直接返回 |
| 二分算法 | 二分答案思想 | 答案范围有序，`check(mid)` 具有单调性；不是直接在数组里找数 |
| 二分算法 | 最大化最小值 | 例如间距最大、最小距离最大；`check(mid)` 判断能否达到该距离 |
| 二分算法 | 最小化最大值 | 例如最大负载最小、最长段最小；`check(mid)` 判断限制是否可行 |
| 二分算法 | check 函数设计 | 把“给定答案是否可行”写清楚；常和贪心、计数、排序结合 |
| 二分算法 | 二分边界陷阱 | `left`、`right` 初值不合理；`mid` 取值导致死循环；`check` 单调方向写反 |
| 递归算法 | 递归基本概念 | 函数直接或间接调用自己；必须有明确终止条件，否则无限递归 |
| 递归算法 | 递归三要素 | 递归函数含义、终止条件、规模缩小方式；先定义“函数负责解决什么” |
| 递归算法 | 调用栈 | 每次递归调用都会保存现场；层数过多可能栈溢出 |
| 递归算法 | 阶乘递归 | `factorial(n) = n * factorial(n-1)`；终止条件 `n==0` 或 `n==1` |
| 递归算法 | 斐波那契递归 | 朴素写法直观但大量重复计算；时间复杂度接近指数级 |
| 递归算法 | 字符串反转 | 首字符/尾字符与剩余字符串递归组合；注意 `substr` 参数含义 |
| 递归算法 | 汉诺塔 | 先移动 `n-1` 个到辅助柱，再移动最大盘，再移动 `n-1` 个到目标柱 |
| 递归算法 | 递归版 gcd | `return b == 0 ? a : gcd(b, a % b);`；考查调用序列和返回值 |
| 递归算法 | 递归与迭代区分 | 递归靠函数调用自己，迭代靠循环更新变量；功能相同但空间开销不同 |
| 递归算法 | 递归时间复杂度 | 单分支递归多为 `O(n)` 或 `O(log n)`；双分支递归可能为 `O(2^n)` |
| 递归算法 | 递归空间复杂度 | 主要看递归深度；阶乘 `O(n)`，二分递归 `O(log n)`，归并排序递归栈 `O(log n)` |
| 递归算法 | 递归优化 | 记忆化搜索、改写为迭代、减少重复调用、剪枝、合理设计参数 |
| 分治算法 | 分治基本思想 | 分解原问题、解决子问题、合并子问题结果；通常用递归实现 |
| 分治算法 | 分治适用条件 | 子问题结构相同且规模更小；子问题结果能合并成原问题结果 |
| 分治算法 | 归并排序思想 | 先把数组分成左右两半分别排序，再合并两个有序序列 |

| 分治算法 | 归并排序复杂度 | 时间复杂度稳定为 `O(n log n)`；通常需要 `O(n)` 额外空间；稳定排序 |
| 分治算法 | 快速排序思想 | 选择基准 pivot，分区后递归排序左右两边 |

| 分治算法 | 分治求最大值 | 左半最大值、右半最大值，合并取 `max`；理解递归树 |

| 贪心算法 | 贪心基本概念 | 每一步选择当前看来最优的方案；不回头、不枚举所有可能 |
| 贪心算法 | 局部最优与全局最优 | 局部最优不一定推出全局最优；题目需要具备贪心选择性质 |
| 贪心算法 | 最优子结构 | 一个问题的最优解包含子问题的最优解；是贪心可行的重要条件之一 |
| 贪心算法 | 贪心选择性质 | 当前选择确定后，不会破坏后续最优解；常需要排序或数学证明 |
| 贪心算法 | 兑换零钱 | 面值特殊时每次选最大不超过剩余金额的硬币；普通面值不一定最优 |
| 贪心算法 | 排序贪心 | 先按某个关键字排序，再顺序选择；关键在于排序规则是否正确 |
| 贪心算法 | 船载人过河 | 常见策略：最轻和最重尝试配对；若超重则最重单独一船 |
| 贪心算法 | 区间与选择 | 选择最早结束、最小代价、最大收益等；考查“为什么这样选” |
| 贪心算法 | 贪心与二分答案 | `check(mid)` 内部常用贪心判断可行性，如最大化最小距离 |
| 贪心算法 | 贪心复杂度 | 排序贪心通常 `O(n log n)`；不排序的一次扫描通常 `O(n)` |
| 贪心算法 | 贪心反例意识 | 不能看到“每步最优”就认定总能最优；需要能举出反例或判断条件 |
| 贪心算法 | 与递推 / DP 区分 | 贪心不保存所有状态；递推/DP 通常需要状态转移和历史最优 |

## 五、错题归因建议

学生错题可以优先按以下方式归类：

1. **初等数论概念错误**
   - 素数、合数、1 的特殊性判断错误
   - 约数、倍数、质因数、真因子概念混淆
   - 最大公约数和最小公倍数公式混乱
   - 欧几里得算法调用顺序和终止条件错误
   - 同余与取模表达式不会转换
   - 唯一分解定理只记名字，不会落到质因数分解
   - 埃氏筛和线性筛的标记规则混淆

2. **复杂度估算错误**
   - 只数循环层数，不看循环变量变化方式
   - 不会区分 `O(log n)`、`O(sqrt(n))`、`O(n log n)`
   - 把递归代码都看成 `O(n)`
   - 把快速排序最坏情况和平均情况混淆
   - 忽略额外数组、递归栈、链表节点带来的空间复杂度

3. **高精度工程实现错误**
   - 字符串、数组两套写法混用导致方向混乱
   - 倒序存储后输出顺序错误
   - 进位、借位、余数更新顺序错误
   - 结果去前导零不会处理
   - 除法从哪一位开始、商如何生成理解不清
   - 没有统一函数接口，导致加减乘除代码风格割裂

4. **链表指针操作错误**
   - 头指针、头结点、哑结点不区分
   - 插入删除时指针修改顺序错误
   - 双链表只改一侧指针，导致链断裂
   - 循环链表终止条件写错
   - 删除后访问已释放节点
   - 只会背代码，不会画节点连接图

5. **二分边界错误**
   - 不知道二分查找必须有序
   - 左闭右闭、左闭右开模板混用
   - 查找具体值、查找边界、二分答案混为一类
   - `mid` 上取/下取与边界更新不匹配
   - `check(mid)` 的含义不清楚
   - 最大化最小值和最小化最大值更新方向写反

6. **递归理解错误**
   - 不会先定义递归函数含义
   - 终止条件不完整
   - 递归参数没有让问题规模变小
   - 忽略递归栈空间
   - 把朴素递归斐波那契的重复计算低估
   - 汉诺塔、字符串反转等参数顺序混乱

7. **分治排序错误**
   - 分治三步“分解、解决、合并”只会背，不会对应代码
   - 归并排序左右区间划分错误
   - `merge` 合并剩余部分遗漏
   - 快速排序 `partition` 过程不会手推
   - 快排最坏情况、稳定性、空间复杂度判断错误
   - 递归边界导致漏排或死递归

8. **贪心建模错误**
   - 只凭直觉选择当前最大/最小，没有证明依据
   - 不会判断题目是否具备贪心选择性质
   - 排序规则写错，导致后续选择全错
   - 把“看起来最优”和“必然最优”混淆
   - 不知道贪心常和排序、双指针、二分答案结合
   - 遇到反例时不能及时转向 DP、枚举或搜索
