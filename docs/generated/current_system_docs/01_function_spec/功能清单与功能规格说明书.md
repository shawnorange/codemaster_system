## 2. 系统概述
CodeMaster System 是基于 Django 5.2 + PostgreSQL 的教学管理系统，当前形态是 Django 模板渲染、本地静态资源和少量 JavaScript 增强的单校区、本地优先教学执行平台。系统不是 SaaS 多租户系统，也不是前后端分离系统；教师端表格主要使用 Tabulator，Homework Stats 页面使用 ECharts。登录体系基于自定义 PortalUser 与签名 Cookie `codemaster_auth`，不是 Django 原生 auth/session。

## 3. 用户角色
### 学生 `student`
使用 PortalUser 学生账号登录；访问课程入口、专题页、作业列表、在线练习、提交详情、打印页和账号设置。数据边界为自己的 Student 档案、自己的作业与提交记录。

### 家长 `parent`
使用 PortalUser 家长账号登录或小程序账号登录；查看绑定孩子档案、作业、提交、总结和打印页。数据边界为 parent_user 绑定的孩子。

### 教师 `teacher`
使用 PortalUser 教师账号登录；访问教师工作台、学生管理、课程结构、内容开放、作业布置/导入/统计、评价、奖励、课时流水。数据边界主要为 teacher_user 或 TeacherStudentAssignment 指向的学生。

### 校长 `principal`
使用 PortalUser 校长账号登录；访问校长概览和学生学习统计 JSON。当前根据代码推断为校区级概览，未在代码中确认多校区隔离。

## 4. 功能模块总览
1. 登录与门户：自定义账号登录、签名 Cookie 下发、按角色跳转到对应门户。
2. 学生端：学生查看课程入口、练习入口和已开放学习内容。
3. 家长端：家长查看绑定孩子档案、作业列表、提交与打印页。
4. 教师工作台：教师入口页，按学生和课程组织工作台内容。
5. 校长端：校长查看校区概览和学生学习统计 JSON。
6. 学生管理：教师查看课程学生、从学生池加入、单个创建学生，并进入学生详情。
7. 教师-学生负责关系：教师新增、编辑、软移除自己名下的学生课程级别负责关系。
8. 课程结构管理：教师按课程、分类、Level 浏览课程结构。
9. 课程级别管理：查看 Level 下知识点，支持筛选和分页。
10. 知识点 / CourseContent 管理：新增、编辑、停用知识点，维护 slug、route_path、summary 和真实内容状态。
11. 学生内容开放权限：教师给学生开放或限制知识点，学生端按权限显示真实内容。
12. 作业布置：教师给单个学生布置作业，可上传题源进入在线题目构建。
13. 作业批量创建：教师选择学生、公共题源或作业要求，批量生成作业并可关联课后总结。
14. 作业导入：支持 PDF、图片、HTML、TXT、DOCX、XLSX 上传，解析候选单选题并由教师确认。
15. 作业提交：学生在线作答选择题，提交后自动保存逐题答案和总成绩。
16. 自动判分 / 结果统计：选择题提交后自动判分，统计页按周/月/季度聚合完成与正确率。
17. Homework Stats：教师查看学生作业完成、正确率、知识点与下钻明细。
18. 作业提交详情：按学生、作业、周期查看提交列表和得分。
19. 作业逐题答案详情：展示某次提交的逐题答案、正确答案快照和解析。
20. 教师评价：教师在学生详情或 Homework Stats 保存评价、亮点和待提升点。
21. 奖励记录：教师给学生添加奖励说明。
22. 课时流水：教师记录课时增减并汇总剩余课时。
23. 题库承接：公共题池导入、知识点即时创建、题源预览和批量作业复用。
24. 管理命令：提供学生导入、题库导入、用户名修复、枚举法题库修复等维护能力。
25. 小程序接口：小程序账号密码登录、微信手机号登录，以及家长/校长学习概览 JSON。

## 8. 关键业务流程
### 用户登录流程
- 参与角色：未登录用户
- 前置条件：用户账号启用且相关模型记录存在。
- 触发入口：访问 `/`
- 主流程：提交 username/password；`authenticate_credentials` 校验 PortalUser；成功后 `set_auth_cookie` 写入 `codemaster_auth` 并按角色跳转。
- 异常流程：账号不存在、密码错误、角色不匹配或 Cookie 过期时返回登录页/重定向。
- 关联模型：PortalUser
- 关联文件：entry/views.py, entry/auth.py
- 后续扩展建议：补充登录失败限流和审计。

### 教师查看学生流程
- 参与角色：teacher
- 前置条件：用户账号启用且相关模型记录存在。
- 触发入口：访问 `/teacher/students` 或课程学生页
- 主流程：role_required 校验教师；portal_context 构建学生、课程和 assignment 汇总；模板使用 Tabulator 展示。
- 异常流程：无权限或学生不存在时 404/重定向。
- 关联模型：Student, TeacherStudentAssignment, Course
- 关联文件：entry/views.py, entry/portal_context.py, teacher_tabulator.js
- 后续扩展建议：大数据量时改为服务端分页 JSON。

### 教师布置作业流程
- 参与角色：teacher
- 前置条件：用户账号启用且相关模型记录存在。
- 触发入口：学生详情页创建作业
- 主流程：选择知识点、标题、说明、截止时间；校验教师负责范围；创建 HomeworkAssignment；同步开放内容权限。
- 异常流程：知识点不在负责范围、日期无效、学生不存在。
- 关联模型：HomeworkAssignment, CourseContent, StudentContentAccess
- 关联文件：entry/views.py, entry/portal_context.py
- 后续扩展建议：抽出 service 并增加事务测试。

### 作业导入流程
- 参与角色：teacher
- 前置条件：用户账号启用且相关模型记录存在。
- 触发入口：作业 builder 或公共题源导入页
- 主流程：上传文件；创建 HomeworkImportJob；调用 `parse_homework_import_job`；本地抽文本/视觉 OCR/qwen/heuristic 生成候选题；教师确认写入 HomeworkQuestion。
- 异常流程：文件类型不支持、外部 API 缺失/超时、候选题为空、提交字段缺失。
- 关联模型：HomeworkImportJob, HomeworkQuestion
- 关联文件：entry/views.py, entry/homework_online.py, entry/homework_batch.py
- 后续扩展建议：增加异步任务队列、重试和人工审核状态。

### 学生提交作业流程
- 参与角色：student
- 前置条件：用户账号启用且相关模型记录存在。
- 触发入口：在线练习页 POST
- 主流程：学生提交 question_* 答案；`grade_homework_submission` 创建 HomeworkSubmission 与 HomeworkSubmissionAnswer；计算正确率和分数；作业标记完成。
- 异常流程：作业取消、无正式题目、非本人作业。
- 关联模型：HomeworkSubmission, HomeworkSubmissionAnswer, HomeworkAssignment
- 关联文件：entry/views.py, entry/homework_online.py
- 后续扩展建议：新增题型需扩展渲染和判分。

### 自动判分 / 统计流程
- 参与角色：student/teacher
- 前置条件：用户账号启用且相关模型记录存在。
- 触发入口：提交后与 Homework Stats
- 主流程：逐题比较 selected_answer 和 correct_answer，写入快照；统计页按周期聚合完成、未完成、正确率、知识点。
- 异常流程：题目后续修改时历史提交依赖快照；未截止作业会被排除或单独计数。
- 关联模型：HomeworkSubmission, HomeworkCompletionStat
- 关联文件：entry/homework_online.py, entry/homework_completion_stats.py, entry/student_learning_api.py
- 后续扩展建议：统计口径需产品确认并测试。

### 教师查看 Homework Stats 流程
- 参与角色：teacher
- 前置条件：用户账号启用且相关模型记录存在。
- 触发入口：`/teacher/homework-stats`
- 主流程：解析 period/anchor_date；获取名下学生；构建周/月/季度摘要；Tabulator 和 ECharts 展示。
- 异常流程：anchor_date 格式错误时回落或 JSON 返回 400。
- 关联模型：Student, HomeworkAssignment, HomeworkSubmission
- 关联文件：entry/views.py, entry/portal_context.py, teacher_homework_stats.html
- 后续扩展建议：图表 CDN 可替换为本地静态资源。

### Submission Detail 下钻流程
- 参与角色：teacher/student/parent
- 前置条件：用户账号启用且相关模型记录存在。
- 触发入口：提交详情路由
- 主流程：从统计或作业页带 student_id/assignment_id/submission_id 下钻，按角色过滤数据后渲染详情。
- 异常流程：跨学生或跨教师访问返回 404。
- 关联模型：HomeworkSubmission, HomeworkAssignment
- 关联文件：entry/views.py, entry/portal_context.py
- 后续扩展建议：统一下钻参数校验和面包屑。

### Submission Answer Detail 下钻流程

- 前置条件：用户账号启用且相关模型记录存在。
- 触发入口：`/teacher/homework-stats/submission-answer-detail`
- 主流程：根据 submission_id 查提交，校验 assignment.teacher 与 student.teacher_user；渲染逐题答案。
- 异常流程：submission 不属于当前教师时 404。
- 关联模型：HomeworkSubmissionAnswer, HomeworkQuestion
- 关联文件：entry/views.py, entry/portal_context.py
- 后续扩展建议：导出时做隐私脱敏。

### 学生内容开放权限流程

### 小程序登录流程
- 参与角色：anonymous/parent/principal
- 前置条件：用户账号启用且相关模型记录存在。
- 触发入口：`/api/miniapp/login` 或 `/api/miniapp/login_by_phone`
- 主流程：账号密码登录允许 parent/principal；手机号登录先调用微信 access_token 和手机号接口，再匹配家长手机号；成功返回 token/user 并写 Cookie。
- 异常流程：JSON 格式错误、微信配置缺失、手机号未绑定或冲突。
- 关联模型：PortalUser, Student
- 关联文件：entry/views.py, entry/auth.py
- 后续扩展建议：上线前增加限流、微信错误码映射和日志脱敏。

## 9. 当前功能边界
- 当前系统不是 SaaS 多租户系统；未在代码中确认 tenant/school 维度的强隔离。
- 当前系统不是 Django Admin 后台；`django.contrib.admin/auth/sessions` 未在 INSTALLED_APPS 中启用。
- 当前系统不是前后端分离项目；大部分交互由 Django 模板返回 HTML。
- 当前系统不是通用 CMS；CourseContent 主要服务教学专题和作业链路。

## 10. 新功能开发建议
- 页面入口和表单处理按现状可放在 `entry/views.py`，但复杂业务建议逐步抽到独立 service，避免 views 继续膨胀。
- 页面上下文、表格行、统计聚合优先放在 `entry/portal_context.py` 或按业务拆分，保持模板只做展示。
- 新增持久化实体或状态字段放在 `entry/models.py`，必须配套 migration 和针对性测试；本次未新增 migration。
- 批量导入、题库修复、一次性维护适合放在 `entry/management/commands/`，生产执行前先 dry-run。
- 涉及作业、权限、学生隐私、手机号、外部 API、上传文件的功能必须新增测试。
- 教师、家长、校长相关功能必须显式考虑数据隔离：teacher_user、TeacherStudentAssignment、parent_user、未来 campus/tenant。
