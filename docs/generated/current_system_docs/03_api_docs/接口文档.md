# CodeMaster System 接口文档

## 1. 文档信息
- 项目名称：CodeMaster System
- 文档版本：v1.0
- 生成时间：2026-05-08 15:09:47 CST
- 生成依据：codemaster_system/urls.py、entry/urls.py、entry/views.py、entry/auth.py、entry/templates/entry/、entry/static/entry/。
- 注意事项：当前项目不是纯 API 项目，多数路由返回 HTML；示例数据全部脱敏，不包含真实 Cookie、密钥、手机号或学生姓名。

## 2. 认证机制
- 自定义账号模型：`entry.models.PortalUser`。
- 登录成功后写入签名 Cookie：`codemaster_auth`，默认 8 小时有效。
- API 还支持 `Authorization: Codemaster <signed-token>`。
- 页面权限：`role_required(role)` 未登录重定向登录页，角色不符跳回当前用户 landing_url。
- JSON 权限：`api_role_required(role)` 未登录返回 401，角色不符返回 403。
- CSRF：Django `CsrfViewMiddleware` 已启用；小程序登录接口使用 `@csrf_exempt`；普通 POST 表单和 fetch POST 需要 CSRF token。
- 非 Django 原生 session/auth：settings.py 未启用 `django.contrib.auth`、`sessions`、`admin`。

## 3. 通用约定
- Base URL：`https://example.com`。
- 返回类型：HTML 页面、JSON、redirect、JSON 下载。
- 参数来源：path、query、form、JSON body、file upload。
- 错误状态：常见为 400、401、403、404、405、500、502，具体见每个视图分支。
- Cookie：示例文档不包含真实 Cookie；测试时使用登录接口获取。

- `/api/miniapp/login`：CSRF exempt，POST JSON，字段 `username`、`password`；仅允许 parent/principal 账号。

- 鉴权方式：成功后返回签名 token，并写入 `codemaster_auth` Cookie。
- 微信接口：`https://api.weixin.qq.com/cgi-bin/token`、`https://api.weixin.qq.com/wxa/business/getuserphonenumber`；文档不包含 appid/secret。
- 安全风险：手机号绑定冲突、微信配置缺失、接口限流、CSRF exempt 登录入口需要额外频控。

## 9. 权限与安全
- 需要登录：所有 `role_required` 和 `api_role_required` 路由。
- 涉及学生数据：学生/家长/教师/校长端几乎全部业务路由。
- 涉及上传文件：作业题源导入、公共题源导入、学生导入、人工修正截图、总结 HTML 上传。
- 涉及外部 API：微信、DashScope、火山 Ark、ECharts CDN。
- 需要 CSRF：普通 POST 表单和非 exempt 的 fetch POST。
- 建议限流或审计：登录、小程序手机号登录、题源导入、学生导入、课时流水、内容权限修改、题目覆盖确认。

## 10. 新功能开发接口建议
- URL 命名保持 `role/domain/action` 风格，URL name 使用短横线。
- JSON API 建议统一 `{error, error_code}` 错误结构和 4xx/5xx 状态。
- 页面 POST 继续使用 CSRF token；纯 API 如需跨端调用需明确 CSRF exempt 与替代鉴权。
- 新接口必须复用 `role_required` / `api_role_required` 或等价权限检查。
- 涉及学生数据的 query/path 参数必须在视图中通过当前角色重新过滤，不信任前端传参。
